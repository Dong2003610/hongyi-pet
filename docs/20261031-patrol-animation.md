# 自动巡逻行走修复

自动巡逻原来只发送一次普通移动动作。人物当前动作的优先级更高时，渲染层可能拒绝切换行走；移动途中收到另一种动作时，主进程仍会继续平移窗口。此外人物窗口原先使用默认后台节流，未获得焦点时动画可能刷新不足。

现在主进程的移动开始和停止指令会同步切换人物状态：向左、向右分别循环已有的五帧走路图，每帧 140ms，停止后恢复待机。巡逻到达屏幕边缘、到时结束或开始拖拽时停止移动；新互动、提醒等动作也会停止原平移。人物窗口关闭后台动画节流。睡觉、进食等原画及原有拖拽行走逻辑保持不变。

验证通过：TypeScript、142 项单元测试、真实 Electron 人物测试和完整集成测试。集成测试捕获原自动巡逻调度器并执行其真实回调，核对左右两种窗口位移、多个行走帧、结束待机及互动停止位移。人物测试核对较高优先级睡姿之后仍能进入行走、两侧各五帧循环、结束后待机。测试使用隔离 profile 和本地模拟新闻、任务数据。

这是源码修复记录，已有便携包需要重新构建后才能包含本次修改。

## 连续两次走路

补充修复同方向重复指令：状态机的 `resume` 去重曾无条件拒绝重启同名状态，即使指令显式要求强制开始。现在明确的互动/移动指令重新计算动画开始时间和持续时间，普通重复更新仍保留 resume 行为。新增单元用例在修改前复现拒绝重启，在修改后验证旧截止时间不会结束第二次行走；界面测试覆盖左右两侧重复帧循环，真实集成测试使用 `take-walk` IPC 验证行走中再次请求及完成后再次请求。
